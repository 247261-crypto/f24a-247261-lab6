18 A promise starts pending

pending — A promise is pending until someone pays it. .then does not run while it is pending.

const receipt = new Promise(function () {});
receipt.then(function () {
  document.querySelector("#out").textContent = "paid";
});
document.querySelector("#out").textContent = "no value yet";

You see no value yet. The line does not become paid.

Second look. A promise with no resolve and no reject stays pending. .then is stored. It is not called.

19 resolve pays the promise

resolve — resolve(value) fulfils the promise with that value. .then receives it.

const receipt = new Promise(function (resolve) {
  resolve("pen");
});
receipt.then(function (item) {
  document.querySelector("#out").textContent = item;
});

You see pen.

Second look. resolve is how you pay. It is a function the promise hands to your executor. It is not a keyword.

<button id="go" type="button">Go</button>

document.querySelector("#go").addEventListener("click", async function () {
const receipt = new Promise(function (resolve) {
  resolve("pen");
});

  document.querySelector("#out").textContent = item;
});
});
</script>

20 It pays once

once — The first resolve wins. A second resolve does nothing.

const receipt = new Promise(function (resolve) {
  resolve("pen");
  resolve("tea");
});
receipt.then(function (item) {
  document.querySelector("#out").textContent = item;
});

You see pen. The word tea is ignored.

Second look. A promise settles once. Fulfilled stays fulfilled. You cannot change pen into tea later.

<button id="go" type="button">Go</button>
<script>
document.querySelector("#go").addEventListener("click", async function () {
const receipt = new Promise(function (resolve) {
  resolve("pen");
  resolve("tea");
});
receipt.then(function (item) {
  document.querySelector("#out").textContent = item;
});
});
</script>

21 A promise and a timer

later — resolve can sit inside a timer. The promise stays pending until that timer runs.

document.querySelector("#out").textContent = "Pending";
const receipt = new Promise(function (resolve) {
  setTimeout(function () {
    resolve("pen");
  }, 400);
});
receipt.then(function (item) {
  document.querySelector("#out").textContent = item;
});

You see Pending, then pen.

Second look. The click function ends while the promise is still pending. .then runs when resolve runs.

<button id="go" type="button">Go</button>
<script>
document.querySelector("#go").addEventListener("click", async function () {
document.querySelector("#out").textContent = "Pending";
const receipt = new Promise(function (resolve) {

    resolve("pen");
  }, 400);
});
receipt.then(function (item) {
  document.querySelector("#out").textContent = item;
});
});
</script>

22 resolve is not return

return — return inside the timer does not pay the promise. Only resolve does.

let paid = "no";
const receipt = new Promise(function () {
  setTimeout(function () {
    return "pen";
  }, 200);
});
receipt.then(function () {
  paid = "yes";
});
setTimeout(function () {
  document.querySelector("#out").textContent = paid;
}, 500);

You see no.

Second look. The timer returned a string to nowhere. The promise was never paid, so then did not set paid to yes.

}, 500);
});
</script>

23 .then receives the value

.then — .then(fn) stores fn. When the promise fulfils, fn is called with the value.

Promise.resolve(50).then(function (n) {
  document.querySelector("#out").textContent = String(n);
});

You see 50.

Second look. Promise.resolve(50) is an already fulfilled promise. .then still runs after the current code, not in the middle of the line.

<p id="out">Ready.</p>
<button id="go" type="button">Go</button>
<script>
document.querySelector("#go").addEventListener("click", async function () {
Promise.resolve(50).then(function (n) { document.querySelector("#out").textContent = String(n); });
});
</script>

24 .then returns the next promise

next promise — The function you pass to .then may return a value. That value fulfils a new promise.

Promise.resolve(50).then(function (n) {
  return n + 1;
}).then(function (n) {
  document.querySelector("#out").textContent = String(n);
});

You see 51.

Second look. The first .then does not write on the page. It returns 51. The second .then receives 51.

<p id="out">Ready.</p>
<button id="go" type="button">Go</button>
<script>
document.querySelector("#go").addEventListener("click", async function () {
Promise.resolve(50).then(function (n) {
  return n + 1;
}).then(function (n) {
  document.querySelector("#out").textContent = String(n);
});
});
</script>

25 A chain reads downward

chain — Each .then is the next step. The steps are written under each other, not inside each other.

Promise.resolve("pen").then(function (item) {
  return item + " 50";
}).then(function (line) {
  document.querySelector("#out").textContent = line;
});

You see pen 50.

Second look. This is the same wait as two nested callbacks. The file reads from top to bottom.

<button id="go" type="button">Go</button>
<script>
document.querySelector("#go").addEventListener("click", async function () {
Promise.resolve("pen").then(function (item) {
  return item + " 50";
}).then(function (line) {
  document.querySelector("#out").textContent = line;
});
});
</script>

26 reject

reject — reject(error) settles the promise as failed. .then does not run. .catch does.

const receipt = new Promise(function (_resolve, reject) {
  reject(new Error("ruler"));
});
receipt.then(function () {
  document.querySelector("#out").textContent = "then";
}).catch(function (err) {
  document.querySelector("#out").textContent = err.message;
});

You see ruler. The word then is not written.

Second look. reject takes the failure. The Error's message is what catch receives.

27 .catch receives the error

.catch — .catch(fn) stores fn for a rejected promise.

Promise.reject(new Error("ruler")).catch(function (err) {
  document.querySelector("#out").textContent = err.message;
});

You see ruler.

Second look. A rejected promise with no .catch is an unhandled rejection. The page can look quiet while the console is red.

<p id="out">Ready.</p>
<button id="go" type="button">Go</button>
<script>
document.querySelector("#go").addEventListener("click", async function () {
Promise.reject(new Error("ruler")).catch(function (err) { document.querySelector("#out").textContent = err.message; });
});
</script>

28 A throw lands in catch

throw — throw inside a .then rejects the promise that .then returned. The next .catch receives it.

Promise.resolve(50).then(function () {
  throw new Error("stopped");
}).catch(function (err) {
  document.querySelector("#out").textContent = err.message;
});

You see stopped.

Second look. You do not have to call reject inside .then. throw is enough. The chain turns it into a rejection.

<script>
document.querySelector("#go").addEventListener("click", async function () {

});
});
</script>

29 One order, by promise

worked chain — A function returns a promise of a price. The next .then multiplies. The last .then writes the total.

function priceOf(item) {
  return new Promise(function (resolve, reject) {
    setTimeout(function () {
      if (item === "pen") resolve(50);
      else reject(new Error("not in the shop"));
    }, 300);
  });
}
priceOf("pen").then(function (price) {
  return price * 2;
}).then(function (total) {
  document.querySelector("#out").textContent = String(total);
});

You see 100.

Second look. priceOf returns a promise, not the number 50. The multiply sits in .then because that is where the number arrives.

<script>
document.querySelector("#go").addEventListener("click", async function () {
function priceOf(item) {
  return new Promise(function (resolve, reject) {

      else reject(new Error("not in the shop"));
    }, 300);
  });
}
priceOf("pen").then(function (price) {
  return price * 2;
}).then(function (total) {
  document.querySelector("#out").textContent = String(total);
});
});
</script>
