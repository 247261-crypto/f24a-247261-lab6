01 A busy loop freezes the page

busy loop — JavaScript runs this loop and does nothing else until the clock passes the end.

const end = Date.now() + 1500;
while (Date.now() < end) {}

You see Frozen. Count does nothing. Then the line says Done.

Second look. A request does not freeze the page. The browser keeps the network. A loop in your own file is what locks the tab.

<p id="out">Ready.</p>
<p id="count">0</p>
<button id="countup" type="button">Count</button>
<script>
document.querySelector("#countup").addEventListener("click", function () {
  const n = Number(document.querySelector("#count").textContent);
  document.querySelector("#count").textContent = String(n + 1);
});
</script>
<button id="go" type="button">Go</button>
<script>
document.querySelector("#go").addEventListener("click", async function () {
document.querySelector("#out").textContent = "Frozen";
setTimeout(function () {
  const end = Date.now() + 1500;
  while (Date.now() < end) {}
  document.querySelector("#out").textContent = "Done";
}, 40);
});
</script>

02 One line at a time

one line — One line runs. The next line waits until that line has finished.

document.querySelector("#out").textContent = "1";
document.querySelector("#out").textContent += " 2";
document.querySelector("#out").textContent += " 3";

You see 1 2 3 in one step. The line never sits on 1 while 2 waits.

Second look. There is no second cashier inside your function. The three writes happen, then the page paints.

<p id="out">Ready.</p>
<button id="go" type="button">Go</button>
<script>
document.querySelector("#go").addEventListener("click", async function () {
document.querySelector("#out").textContent = "1";
document.querySelector("#out").textContent += " 2";
document.querySelector("#out").textContent += " 3";
});
</script>

03 The browser keeps the clock

timer — You hand a function and a delay to the browser. The browser keeps the clock. Your next line runs at once.

setTimeout(function () {
  document.querySelector("#out").textContent += " · later";
}, 400);
document.querySelector("#out").textContent = "now";

You see now, then now · later.

Second look. The timer does not pause the function. The word now is written while the clock is still running.

<p id="out">Ready.</p>
<button id="go" type="button">Go</button>
<script>
document.querySelector("#go").addEventListener("click", async function () {
setTimeout(function () {
  document.querySelector("#out").textContent += " · later";
}, 400);
document.querySelector("#out").textContent = "now";
});
</script>

04 The browser keeps the network

request — fetch hands the request to the browser. The next line runs before the reply arrives.

document.querySelector("#out").textContent = "asked";
const response = await fetch("/api/price?item=pen");
const data = await response.json();
document.querySelector("#out").textContent = "asked · " + data.item + " " + data.price;

You see asked, then asked · pen 50. Start the server. Open this page from localhost.

Second look. The wait belongs to the browser. Your function parked at await. The line asked was already on the page.

<p id="out">Ready.</p>
<button id="go" type="button">Go</button>
<script>
document.querySelector("#go").addEventListener("click", async function () {
document.querySelector("#out").textContent = "asked";
const response = await fetch("/api/price?item=pen");
const data = await response.json();
document.querySelector("#out").textContent = "asked · " + data.item + " " + data.price;
});
</script>

05 setTimeout runs later

setTimeout — setTimeout(fn, ms) runs fn no sooner than ms milliseconds from now.

setTimeout(function () {
  document.querySelector("#out").textContent = "later";
}, 400);

You see later after a short wait. The click itself does not write later.

Second look. 400 is the earliest time, not a promise of the exact millisecond. A busy page can run fn a little after that.

<p id="out">Ready.</p>
<button id="go" type="button">Go</button>
<script>
document.querySelector("#go").addEventListener("click", async function () {
setTimeout(function () { document.querySelector("#out").textContent = "later"; }, 400);
});
</script>

06 The line under the timer runs now

next line — The line under setTimeout is not inside the timer. It runs before the timer function.

setTimeout(function () {
  document.querySelector("#out").textContent += " B";
}, 300);
document.querySelector("#out").textContent = "A";

You see A, then A B.

Second look. People read the file top to bottom and expect B first. The call schedules B. The write of A is the next real line.

<p id="out">Ready.</p>
<button id="go" type="button">Go</button>
<script>
document.querySelector("#go").addEventListener("click", async function () {
setTimeout(function () { document.querySelector("#out").textContent += " B"; }, 300);
document.querySelector("#out").textContent = "A";
});
</script>

07 A delay of zero

zero — setTimeout(fn, 0) still runs fn later. Zero means after the current code finishes.

setTimeout(function () {
  document.querySelector("#out").textContent += " · zero";
}, 0);
document.querySelector("#out").textContent = "after";

You see after, then after · zero.

Second look. Zero does not mean now. The current function gets to the end. Then the queued function runs.

<button id="go" type="button">Go</button>
<script>
document.querySelector("#go").addEventListener("click", async function () {
setTimeout(function () { document.querySelector("#out").textContent += " · zero"; }, 0);
document.querySelector("#out").textContent = "after";
});
</script>

08 The shorter timer finishes first

shorter — Two timers run on the browser clock. The one with the smaller delay is ready first.

setTimeout(function () {
  document.querySelector("#out").textContent += " slow";
}, 600);
setTimeout(function () {
  document.querySelector("#out").textContent = "fast";
}, 200);

You see fast, then fast slow.

Second look. The order in the file is slow, then fast. The order on the page is the order the clock finishes.

<p id="out">Ready.</p>
<button id="go" type="button">Go</button>
<script>
document.querySelector("#go").addEventListener("click", async function () {
setTimeout(function () { document.querySelector("#out").textContent += " slow"; }, 600);
setTimeout(function () { document.querySelector("#out").textContent = "fast"; }, 200);
});
</script>

09 Finished jobs wait in a queue

queue — When a timer finishes, its function joins a queue. The queue runs after the current code.

document.querySelector("#out").textContent = "start";
setTimeout(function () {
  document.querySelector("#out").textContent += " 1";
}, 0);
setTimeout(function () {
  document.querySelector("#out").textContent += " 2";
}, 0);
setTimeout(function () {
  document.querySelector("#out").textContent += " 3";
}, 0);

You see start, then start 1 2 3.

Second look. Three delays of zero still wait. They run in the order they were queued, after start is on the page.

<p id="out">Ready.</p>
<button id="go" type="button">Go</button>
<script>
document.querySelector("#go").addEventListener("click", async function () {
document.querySelector("#out").textContent = "start";
setTimeout(function () { document.querySelector("#out").textContent += " 1"; }, 0);
setTimeout(function () { document.querySelector("#out").textContent += " 2"; }, 0);
setTimeout(function () { document.querySelector("#out").textContent += " 3"; }, 0);
});
</script>

10 Predict the print order

order — Read the lines that run now. Then read the lines that were queued.

document.querySelector("#out").textContent = "A";
setTimeout(function () {
  document.querySelector("#out").textContent += " B";
}, 0);
document.querySelector("#out").textContent += " C";

You see A C, then A C B.

Second look. B was scheduled first in the file and printed last. C is under the timer, so C is part of the current run.

<p id="out">Ready.</p>
<button id="go" type="button">Go</button>
<script>
document.querySelector("#go").addEventListener("click", async function () {
document.querySelector("#out").textContent = "A";
setTimeout(function () { document.querySelector("#out").textContent += " B"; }, 0);
document.querySelector("#out").textContent += " C";
});
</script>
