38 fetch

fetch — fetch(url) returns a promise of a Response. The status and the headers are on that object.

const response = await fetch("/api/price?item=pen");
document.querySelector("#out").textContent = String(response.status);

You see 200. Start the server. Open this page from localhost.

Second look. fetch does not return the price. It returns a promise of the reply envelope.

<p id="out">Ready.</p>
<button id="go" type="button">Go</button>
<script>
document.querySelector("#go").addEventListener("click", async function () {
const response = await fetch("/api/price?item=pen");
document.querySelector("#out").textContent = String(response.status);
});
</script>

40 The status code

status — response.status is the number the server sent. 200 means the item was found.

const response = await fetch("/api/price?item=pen");
document.querySelector("#out").textContent = String(response.status);

You see 200.

Second look. The number is on the response. You do not await status. You await fetch, then read status.

41 json is a second promise

json — response.json() returns a promise of the parsed body. Without await you hold that promise.

const response = await fetch("/api/price?item=pen");
const data = response.json();
document.querySelector("#out").textContent = String(data);

You see [object Promise].

Second look. One await on fetch is not enough. The body is a second step.

42 Two awaits

two awaits — The first await gets the response. The second await gets the object in the body.

const response = await fetch("/api/price?item=pen");
const data = await response.json();
document.querySelector("#out").textContent = data.item + ": Rs " + data.price;

You see pen: Rs 50.

Second look. data.item and data.price exist after the second await. Before that, data is a promise.

43 response.ok

ok — response.ok is true when the status is in the 200s. It is false for 404.

const response = await fetch("/api/price?item=ruler");
document.querySelector("#out").textContent = String(response.ok) + " " + response.status;

You see false 404.

Second look. ok is a boolean already computed from the status. You still have a response object.

44 A 404 does not throw

404 — fetch fulfils on 404. catch does not run. You read ok and decide.

fetch("/api/price?item=ruler").then(function (response) {
  document.querySelector("#out").textContent = String(response.status) + " · catch did not run";
}).catch(function () {
  document.querySelector("#out").textContent = "catch ran";
});

You see 404 · catch did not run.

Second look. The store computer answered. The answer was that ruler is not in the shop. An answer is not a dead line.

45 Axios throws on a 404

Axios — Axios is a library. On a 404 it rejects, so catch runs. fetch on that same 404 fulfils.

const response = await fetch("/api/price?item=ruler");
document.querySelector("#out").textContent = String(response.status) + " · fetch did not throw";

You see 404 · fetch did not throw.

Second look. This lab uses fetch, which is already in the browser. Axios would have thrown on this 404. You would meet that throw in catch.

46 No reply throws

no reply — fetch rejects when no response arrives. A stopped server, a closed port.

try {
  await fetch("http://127.0.0.1:9/api/price?item=pen");
  document.querySelector("#out").textContent = "a reply arrived";
} catch (err) {
  document.querySelector("#out").textContent = "The server is not answering";
}

You see The server is not answering.

Second look. Nothing came back, so there is no status to read. catch is the only branch.

<p id="out">Ready.</p>
<button id="go" type="button">Go</button>
<script>
document.querySelector("#go").addEventListener("click", async function () {
try {
  await fetch("http://127.0.0.1:9/api/price?item=pen");
  document.querySelector("#out").textContent = "a reply arrived";
} catch (err) {
  document.querySelector("#out").textContent = "The server is not answering";
}
});
</script>

47 Two different failures

two failures — A 404 writes one sentence. A dead server writes a different sentence.

const response = await fetch("/api/price?item=ruler");
if (!response.ok) {
  document.querySelector("#out").textContent = "ruler is not in the shop";
}

You see Ruler shows ruler is not in the shop. The closed port shows The server is not answering.

Second look. One sentence cannot stand in for both. ok handles the reply that says no. catch handles silence.

<p id="out">Ready.</p>
<button id="ruler" type="button">Ruler</button>
<button id="dead" type="button">Closed port</button>
<script>
document.querySelector("#ruler").addEventListener("click", async function () {
  const response = await fetch("/api/price?item=ruler");
  if (!response.ok) {
    document.querySelector("#out").textContent = "ruler is not in the shop";
  }
});
document.querySelector("#dead").addEventListener("click", async function () {
  try {
    await fetch("http://127.0.0.1:9/api/price?item=pen");
  } catch (err) {
    document.querySelector("#out").textContent = "The server is not answering";
  }
});
</script>
