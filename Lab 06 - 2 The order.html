This is project 2. You build it when the last digit of your roll, divided by 3, leaves a remainder of 2. Digits 2, 5, and 8.

A desk at your place. The ticket, the sheet, and the takings are three parts of the same desk. A person writes the item and how many, and sends it. The ticket shows the order number, the item, and the total the computer just sent. The sheet keeps every order. Count is how many rows are on the sheet. Takings is those totals added. Drop last removes the last row. When that row is the one on the ticket, the ticket goes blank. Ruler adds no row and leaves the ticket as it was. A quantity that is not a whole number from 1 upward does not send. A stopped computer adds no row and leaves the ticket and the takings as they were.

This is order.html. Your place and your header colour come from the last digit of your roll. The place name is white.

The finished order

order.html
  header     your place, your colour, the name in white
  status     id="status"     one sentence in the file
  ticket     id="ticket"
             id="ticket-id"      empty in the file
             id="ticket-item"    empty in the file
             id="ticket-total"   empty in the file
  sheet      Order | Item | Qty | Total
             id="sheet"          no rows in the file
  figures    id="count"      starts at 0
             id="takings"    starts at 0
  form       id="order"
             id="item"  name="item"
             id="qty"   name="qty"
             button id="send"    type submit
             button id="drop"    Drop last
  footer     your roll

Topic 1 — The page

  • The page is order.html in f24a-YOURROLL-lab6.
  • The heading is your place. The header uses your colour. The place name is white. The footer shows your roll.
  • Commit with the message 2 The order — The page.

Topic 2 — The ticket

  • Put a status line on the page. Its id is status. The file contains one sentence in that line.
  • The ticket id is ticket. The order number id is ticket-id. The item id is ticket-item. The total id is ticket-total. All three are empty in the file.
  • Commit with the message 2 The order — The ticket.

Topic 3 — The sheet

  • The sheet headings are Order, Item, Qty, and Total. The body id is sheet. The file has no order rows.
  • Count id is count and starts at 0. Takings id is takings and starts at 0.
  • Commit with the message 2 The order — The sheet.

Topic 4 — The form

  • The form id is order. The item box id is item and its name is item. The quantity box id is qty and its name is qty.
  • Send is send, type submit. Drop last is drop, type button. The words on it are Drop last.
  • Commit with the message 2 The order — The form.

Topic 5 — The server file

  • Copy server.js into this folder. Do not change it.
  • Run node server.js. Open http://localhost:3016/order.html.
  • Commit with the message 2 The order — The server file.

Topic 6 — Send is stored

  • Send is a submit listener on the form. Drop last is a click listener. Neither line calls its function. Loading the page adds no row.
  • Send stays on this page. The address bar does not change.
  • Commit with the message 2 The order — Send is stored.

Topic 7 — A bad quantity

  • A quantity that is not a whole number from 1 upward does not send. The status line says not a number. The sheet, the ticket, Count, and Takings stay as they are.
  • That check uses setCustomValidity with the message not a number, then reportValidity. A later good send clears that message with an empty string.
  • Commit with the message 2 The order — A bad quantity.

Topic 8 — Loading

  • A good quantity sets the status line to Loading… and Send stops taking clicks.
  • Commit with the message 2 The order — Loading.

Topic 9 — The ticket and the sheet

  • Restart the server so the first order number is 1. Send pen and 2.
  • The status line says Order 1, total 100. The ticket shows 1, pen, and 100. The sheet has that row. Count shows 1. Takings shows 100.
  • Send tea and 1. The ticket shows 2, tea, and 40. The sheet has both rows. Count shows 2. Takings shows 140.
  • The digits 50, 80, 40, 100, and 140 are not written in order.html. They are not written in the page script. The prices stay inside server.js. Takings is the totals on the sheet added together.
  • Commit with the message 2 The order — The ticket and the sheet.

Topic 10 — Drop last

  • From the two rows above, Drop last removes tea. The sheet keeps pen, 2, 100. Count shows 1. Takings shows 100. The ticket is blank, because the dropped row was the one on the ticket.
  • Drop last on an empty sheet changes nothing.
  • Commit with the message 2 The order — Drop last.

Topic 11 — A name that is not there

  • Send ruler and 1. The status line says ruler is not in the shop. The sheet does not grow. The ticket stays as it was. Count and Takings stay as they were.
  • Commit with the message 2 The order — A name that is not there.

Topic 12 — The computer is off

  • Stop node. Send pen and 1.
  • The status line says The server is not answering. The sheet does not grow. The ticket, Count, and Takings stay as they were.
  • Commit with the message 2 The order — The computer is off.

Topic 13 — The button comes back

  • After a row is added, Send takes a click again.
  • After ruler, Send takes a click again.
  • After the computer is off, Send takes a click again.
  • Commit with the message 2 The order — The button comes back.

Topic 14 — The sentence in the file

  • Refresh brings that sentence back. The ticket is empty. The sheet is empty. Count is 0. Takings is 0.
  • Commit with the message 2 The order — The sentence in the file.
