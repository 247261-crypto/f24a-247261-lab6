11 A callback is handed over

callback — A callback is a function you pass to someone else. They call it later.

function later(fn) {
  setTimeout(fn, 300);
}
later(function () {
  document.querySelector("#out").textContent = "ran";
});

You see ran after a short wait.

Second look. The name later does not know what the function does. It only knows it must call that function.

<script>
document.querySelector("#go").addEventListener("click", async function () {
function later(fn) {
  setTimeout(fn, 300);
}
later(function () {
  document.querySelector("#out").textContent = "ran";
});
});
</script>

12 Parentheses call it now

parentheses — The name of a function hands it over. Parentheses after the name call it on this line.

function ping() {
  return "ping";
}
const handed = ping;
const called = ping();

You see The first button shows function. The second button shows ping.

Second look. addEventListener("click", loadShelf()) with parentheses runs loadShelf while the script is loading. The listener never gets stored.

<p id="out">Ready.</p>
<button id="hand" type="button">Hand the name</button>
<button id="call" type="button">Call it</button>
<script>
function ping() { return "ping"; }
document.querySelector("#hand").addEventListener("click", function () {
  const handed = ping;
  document.querySelector("#out").textContent = typeof handed;
});
document.querySelector("#call").addEventListener("click", function () {
  document.querySelector("#out").textContent = ping();
});
</script>

13 The callback carries the answer

answer — The function that calls you can pass a value in. That value is the answer.

function later(fn) {
  setTimeout(function () {
    fn(50);
  }, 300);
}
later(function (n) {
  document.querySelector("#out").textContent = String(n);
});

You see 50.

Second look. The 50 is not a return to later's caller. later already finished. The 50 arrives as an argument to your function.

14 return stays inside the timer

return — return inside the timer's function ends that function. It does not become the caller's result.

function ask() {
  setTimeout(function () {
    return 50;
  }, 0);
  return "caller already finished";
}
document.querySelector("#out").textContent = ask();

You see caller already finished. The 50 is thrown away.

Second look. The caller had already returned before the timer ran. There is nowhere for that 50 to land.

</script>

15 The caller does not wait

caller — A variable written inside the timer is still the old value on the next line.

let box = "empty";
setTimeout(function () {
  box = "50";
}, 400);
document.querySelector("#out").textContent = box;
setTimeout(function () {
  document.querySelector("#out").textContent = box;
}, 500);

You see empty, then 50.

Second look. Reading box on the next line does not subscribe to the timer. The second timer is a separate later read.

16 Two steps, nested

two steps — The second timer is written inside the first callback, so it starts when the first one runs.

setTimeout(function () {
  document.querySelector("#out").textContent = "1";
  setTimeout(function () {
    document.querySelector("#out").textContent = "1 2";
  }, 300);
}, 300);

You see 1, then 1 2.

Second look. The second 300 milliseconds start after the first callback, not when the click happens.

<button id="go" type="button">Go</button>
<script>
document.querySelector("#go").addEventListener("click", async function () {
setTimeout(function () {

  }, 300);
}, 300);
});
</script>

17 Three steps, nested

pyramid — Each next step sits inside the previous callback. A fourth step would sit inside the third.

setTimeout(function () {
  document.querySelector("#out").textContent = "1";
  setTimeout(function () {
    document.querySelector("#out").textContent = "1 2";
    setTimeout(function () {
      document.querySelector("#out").textContent = "1 2 3";
    }, 250);
  }, 250);
}, 250);

You see 1, then 1 2, then 1 2 3.

Second look. This shape is why the later headings exist. A chain and await do the same wait without packing each step inside the last one.
